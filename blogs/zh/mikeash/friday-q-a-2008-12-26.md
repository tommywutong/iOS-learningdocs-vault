Friday Q&A 2008-12-26：Blocks 初探

作者：[Mike Ash](https://www.mikeash.com/)

“blocks” 这个词有点含糊，所以先澄清一下，我指的不是 C 语言自诞生以来就存在的复合语句结构。我说的是 Apple 正在为语言创建的一个新特性，它为语言添加了匿名函数。

由于它们还没有以最终形式向公众开放，因此在语法方面的讨论会有些不够精确。但这并不是大问题，因为我主要想讨论的是它们能为我们做什么，而不是如何打出它们的绝对精确细节。首先来看看它们的样子：

```
    x = ^{ printf("hello world\n"); }
```

这就是一个 block。大括号前面那个奇怪的脱字符（^）就是它和无聊的旧式复合语句的区别所在。现在我们可以像这样简单地调用这个 block：

```
    x();
```

生成的代码会打印出 “hello world”。现在引入几个参数：

```
    x = ^(int a, char *b){ printf("a is %d and b is %s", a, b); }
```

然后我们可以像你想象的那样调用它：

```
    x(42, "fork!");
```

现在再移除参数：

```
    int a = 42;
    char *b = "fork!";
    x = ^{ printf("a is %d and b is %s", a, b); }
    x();
```

这展示了 blocks 一个真正有趣的特性：它们可以捕获其封闭作用域中的变量。在这里这并不特别有趣（为什么我们不直接在调用时传递 a 和 b 呢？）但当我们开始把 block 传递给其他函数时，它就变得真正有趣了：

```
    int a = 42;
    char *b = "fork!";
    callblock(^{ printf("a is %d and b is %s", a, b); });
```

当 `callblock()` 函数调用那个 block 时，block 仍然能访问我们的局部变量 a 和 b，尽管我们从未显式地将它们传递给该函数。

关于 blocks 的基础知识差不多就介绍完了。再来一个快速示例，一个返回值的 block：

```
    x = ^(int n){ return n + 1; };
    printf("%d\n", x(2));
```

这段代码会打印出 “3”。注意，不需要声明返回值的类型，因为编译器可以直接从 return 语句推断出来。

那么这有什么大不了的？blocks 的一个主要优势是，它们本质上允许你在语言中编写自己的控制结构，而无需修改编译器。举个例子，来看看 Leopard 中出现的 `for(... in ...)` 语法。这个语法是对语言的一个极好补充。以前我们必须编写一堆代码才能遍历一个数组：

```
    NSEnumerator *enumerator = [array objectEnumerator];
    id obj;
    while((obj = [enumerator nextObject]))
        // 终于可以用 obj 做点什么了
```

而新语法把这缩减到一行：

```
    for(id obj in array)
```

这很好。唯一的麻烦是我们等了很久很久才拥有它。我们不得不等待 Apple 为我们添加它。有了 blocks，再也不需要了！你得不到完全相同的语法，但你可以通过完全自己编写的方法获得同样的便利性：

```
    my_for(array, ^(id obj){ /* 循环体放在这里 */ });
```

或者以一种可能稍微奇怪但更有趣的面向对象形式：

```
    [array do:^(id obj){ /* 循环体放在这里 */ }];
```

`-do:` 方法的实现留给读者自己完成，但请放心，它相对简单。

作为另一个例子，考虑 `@synchronized` 指令。它也可以用 blocks 来重做：

```
    [obj synchronized:^{ /* 这里受锁保护 */ }];
```

好吧，你说，我明白了，但这有什么大不了的？毕竟 `for/in` 和 `@synchronized` 已经是语言的一部分了，为什么还要重写它们？

当然你不会。那样会很傻。这些示例只是为了说明一个想法：你可以构建自己的控制结构。但当然，只有构建**新**的控制结构才有趣！所以这里有一些想法。

- 打开一个文件并确保在完成后关闭它：

  ```
      [[NSFileHandle fileHandleForReadingAtPath:path]
        closeWhenDone:^(NSFileHandle *handle){
          /* 在这里使用 handle */
      }];
  ```
- 通过处理现有数组中的对象来构建一个新数组：

  ```
      newArray = [existingArray map:^(id obj){ return [obj stringByAppendingString:@"suffix"]; }];
  ```
- 过滤数组的内容：

  ```
      newArray = [existingArray filter:^(id obj){ return [obj hasPrefix:@"my"]; }];
  ```
- 主线程同步：

  ```
      /*  线程代码 */
      PerformOnMainThread(^{ /* 同步代码 */ });
      /* 更多线程代码 */
  ```
- 延迟执行：

  ```
      PerformWithDelay(5.0, ^{ /* 将在 5 秒后运行 */ });
  ```
- 并行枚举：

  ```
      [array doParallelized:^(id obj){
          /* 将同时在你的所有 CPU 核心上执行 */
      }];
  ```

还有无数其他例子。

blocks 会让事情变得更好的另一个地方是处理回调。如果你写过大量的 Cocoa 代码，你可能不得不编写过表单（sheet）回调，那真是件痛苦的事。如果你需要把变量传递到另一边，处理像这样的代码会变得非常令人沮丧：

```
   - (void)method {
        int foo;
        NSString *bar;
        /* 用这些变量做一些工作 */
        NSDictionary *ctx = [[NSDictionary alloc] initWithObjectsAndKeys:
            [NSNumber numberWithInt:foo], @"foo",
            bar, @"bar",
            nil];
        [NSApp beginSheet:sheet
            modalForWindow:window
            modalDelegate:self
            didEndSelector:@selector(methodSheetDidEnd:returnCode:contextInfo:)
            contextInfo:ctx];
    }
    
    - (void)methodSheetDidEnd:(NSWindow *)sheet returnCode:(int)code contextInfo:(void *)ctx {
        NSDictionary *ctxDict = ctx;
        [ctxDict autorelease];
        
        int foo = [[ctxDict objectforKey:@"foo"] intValue];
        NSString *bar = [ctxDict objectForKey:@"bar"];
        /* 用这些变量再做些其他事 */
    }
```

哇！真是麻烦。因为我去掉了所有实际做事的代码，剩下的几乎全是样板代码。可怕的样板代码，其唯一目的就是告诉表单要调用谁，并把局部信息打包成表单以后能返回给你的形式。现在让我们想象我们用 blocks 重做这个 API，看看会是什么样子：

```
    - (void)method {
        int foo;
        NSString *bar;
        /* 用这些变量做一些工作 */
        [sheet beginSheetModalForWindow:window didEndBlock:^(int code){
            /* 用 foo 做些事 */
            /* 用 bar 做些事 */
            /* 用 code 或 sheet 或 window 或任何东西做些事 */
        }];
    }
```

这难道不棒吗？那些可怕的样板代码就这么飞出了窗外。代码流程突然间变得完全合乎逻辑，你可以从上到下阅读它，而且你可以访问你想要的任何局部变量。

让我们再举一个例子，用一个你传入的带变量的自定义比较函数对数组排序。NSArray 有用于此的功能，即 `-sortedArrayUsingFunction:context:` 方法。老式代码很烦人，我就不写了。它很像上面的表单方法。你必须单独定义一个函数，离你的代码很远，几乎不可见。你必须设置要传入它的上下文。如果你要传入不止一个东西，那么你必须传入一个字典（并解包它）或一个指向结构体的指针。下面是 blocks 版本的自定义比较器：

```
   sorted = [array sortedArrayUsingBlock:^(id a, id b){
        /* 进行比较，使用局部变量来决定做什么，尽情发挥 */
    }];
```

仅此而已。

回调是 C 和 Objective-C 中最强大的东西之一，但在许多情况下，它们的使用可能极其困难且不自然。Blocks 有望让回调和自定义控制结构的创建和使用变得更加自然。

到目前为止，我只展示了使用 blocks API 的示例，但如何创建一个呢？嗯，稍微麻烦一点，但不多。唯一的问题是声明 block 类型的语法有点丑陋，因为它模仿了函数指针的语法。但这还不算太糟，其余部分都简洁明了。例如，下面是你如何编写上面提到的 `-map:` 方法：

```
    - (NSArray *)map:(id (^)(id))block { // 接受一个 id，返回一个 id
        NSMutableArray *ret = [NSMutableArray array];
        for(id obj in self)
            [ret addObject:block(obj)];
        return ret;
    }
```

相当直接，尤其是考虑到它赋予我们的能力。

关于 Apple 实现 blocks 的信息仍然有点稀少。更多细节可以在 Clang 开发邮件列表的[一封邮件](http://lists.cs.uiuc.edu/pipermail/cfe-dev/2008-August/002670.html)中找到。要想获得关于如何使用 blocks 的更多纯概念性想法，可以看看 Smalltalk 语言，在该语言中，blocks 被用于几乎每一个控制结构，包括 if/then 和基本循环。希望 blocks 能让我们在 Snow Leopard 上的工作方式发生重大变化！
