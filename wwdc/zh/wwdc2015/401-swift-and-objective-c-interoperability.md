一个 nullability 限定符，就是你可以加在一个 C/Objective-C 指针上、用来表明它是否接受 nil 的东西。当然，这样能更好地传达你的 API 实际在做什么。它接受 nil 吗？这对它来说有意义吗？这能帮我们的工具做更好的静态检查，在 bug 出现在运行时之前就把它们抓出来，而且它能让你的 Objective-C API 在 Swift 里的使用体验好得多！现在，一共有三种 nullability 限定符。

Nullable，表示这个指针可能是 null。

这个，当然会映射成一个 Swift 可选值。

然后是 non-null。表示 null 或者 nil 在这里不是一个有意义的值。

不过，对于一个 non-null 的指针来说，它在一个 Objective-C 程序里最终还是有可能是 nil 的。也许是因为我们在某个时刻给 nil 发了消息，然后这个 nil 一路传播下去了，而这在过去也许一直能正常工作。编译器不会因为一个 non-null 标注就改变它生成代码的方式。但这标明了 API 作者的意图：在这里，nil 是没有意义的。我们还有第三种限定符，那就是 null-unspecified。

这是用在既不适合用 nullable、也不适合用 non-null 的情况下的，我们会把它映射成 Swift 里的隐式解包可选值——就跟我们对这个指针一无所知时得到的结果一样。而关于 nullability 限定符，最重要的一点是：我们已经在我们的 SDK 里全面铺开了它。
