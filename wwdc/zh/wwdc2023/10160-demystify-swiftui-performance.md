当 App 中的数据发生变化时，更少的更新意味着更好的性能。正如我们刚才探索的，一种方法是减少依赖。尝试将视图值减少到它们实际依赖的数据。另一个技巧是提取视图以减少依赖。最后，新的 Observable 协议也可以通过自动将依赖限制为仅被读取的部分来帮助依赖范围化。请查看《探索 SwiftUI 中的观察》这个 session 以获得更多信息。

这只是关于如何查看依赖的快速介绍。让我们继续讨论更快的更新。在本节中，我们将讨论如何降低每次 SwiftUI 更新的成本。缓慢的 SwiftUI 更新会对你的 App 产生许多负面影响，包括降低响应性，例如挂起（hang）和卡顿（hitch）。挂起是响应用户交互的延迟，比如视图初始出现花费很长时间。WWDC2023 的《使用 Instruments 分析挂起》这个 session 详细介绍了如何使用 Instruments 分析挂起，包括如何识别挂起是否可能由 SwiftUI 相关的工作引起。卡顿是用户可感知的动画问题，例如滚动期间的停顿或动画的跳帧。挂起和卡顿的根本原因，尤其是在 SwiftUI 中，通常是相关的。有关卡顿的更多信息，包括系统渲染循环如何工作，请查看《探索 UI 动画卡顿与渲染循环》技术讲座视频。SwiftUI 中的挂起和卡顿通常源于缓慢的更新。

这些缓慢的更新有几个常见原因。第一个是昂贵的动态属性实例化，例如分配并初始化状态对象（state object）或初始化 State。另一个来源是在 body 中完成的工作。确保检查 body 中是否有昂贵的字符串插值或像数据过滤这样的操作以及其他工作。body 本身尽可能轻量很重要。这些都是相互关联的。例如，一个动态属性可能从视图的 body 中计算得到，这使得视图的求值变得昂贵。慢速识别也经常发生在视图的 body 中。让我们从 fetch App 中的一个例子开始。

解决这个问题的一种方法是使用 task 修饰符。我们首先将获取操作改为异步。我在这里只展示了添加 async 关键字。接下来，在 task 修饰符中，我们将通过等待（await）来异步获取狗狗列表。这样，当昂贵的加载数据操作发生时，App 仍然保持响应。还有其他你可能没意识到影响 App 的工作来源。例如，字符串插值通常可能很昂贵，所以确保缓存你可能需要频繁使用的任何字符串。类似地，从 bundle 中查找值可能很昂贵。当然，任何堆分配，例如为类绑定类型进行的分配，都会累积起来。让我们继续讨论列表和表格。

列表和表格支持超越简单布局的丰富特性，增加了选择、滑动操作、重新排序支持等。这些是复杂的、高级的控件，理解身份对于确保它们在 App 中具有良好的性能至关重要。在本节中，我将讨论列表和表格中的身份，并揭开如何最大化这些内置组件的更新性能。在深入探讨这个主题之前，我想提一些改进。在 macOS Sonoma 和 iOS 17 中，SwiftUI 在后台针对诸如过滤和滚动等情况进行了许多优化。这些改进只需你付出极少的努力即可获得，并且在许多情况下，可以显著提高较大列表和表格的加载和更新时间响应速度。然而，有一些构建列表和表格的方法能带来更好的性能。

列表和表格使用标识符来知晓数据发生了哪些变化。为了保持一致性，列表和表格的所有 ID 都会被急切地收集。因此，能够为你的列表和表格内容快速生成标识符，直接转化为更快的加载和更新时间。身份帮助 SwiftUI 管理视图生命周期，这对于视图层级结构的增量更新至关重要。身份的改变意味着视图发生了改变。这对动画和性能很重要。有关动画的更多信息，请查看《SwiftUI 动画基础》这个 session。识别性能很重要，因为标识符经常被收集，尤其是对于列表和表格。让我们来浏览一下列表的识别模型。
