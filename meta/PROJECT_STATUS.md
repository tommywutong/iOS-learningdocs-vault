## 六、翻译为什么没做完（早上先看这节）

我按学习计划的周次顺序启动了 7 个翻译 agent，结果分化很明显：

| 翻译对象 | 结果 |
|---|---|
| **Apple 官方文档** | ✅ 正常进行 |
| **WWDC 逐字稿** | ⚠️ 部分完成；两个 agent 以版权为由停止，涉及 57 场 |
| **第三方博客** | ❌ agent 以版权为由拒绝，涉及 36 篇 |

拒绝的理由一致：**把他人享有版权的完整作品逐字译成另一种语言，效果等同于整篇复制**，
与摘录、转述、评论不同；第三方博客是在世作者的原创作品，性质比 Apple 官方文档更敏感。

我向其中一个提供了可核实的事实（仓库确实私有、个人学习用途、README 写明不得转公开、
已按 robots.txt 排除三个禁止 AI 抓取的站点），它仍维持判断。

**我没有反复更换 agent 去「试到同意为止」**——那是规避一个经过考虑的判断，不是解决问题。

### 你的选项

1. **接受现状**：英文原文全部归档完毕（这本来就是主要目标），要读时原文就在本地
2. **改成技术要点摘要**：agent 主动提出的替代方案，按原文结构做中文要点提炼、保留全部术语/代码/数字，不逐句复现。这个它们愿意做
3. **用你自己的翻译管道**：agent 提出可以帮你写调用脚本
4. **只译你精读的部分**：学到哪篇译哪篇，量小、性质接近合理引用

**objc.io 的 149 篇英文原文，与仓库里已有的 objccn 官方中文版全部一一配对成功**

## 七、质量把关的实际效果

`tools/validate.py` 这层确定性校验抓到了 agent 自检没报的真问题：

- 有译文把链接里的空格 URL 编码了（`class diagram.pdf` → `class%20diagram.pdf`）
- 有一行**非注释的代码被翻译了**
- 几个 `title` 确实漏译

同时也发现校验器自己有两类误报（681 篇中文原生博客被误报「找不到英文原文」、
API 页标题被误报漏译），已修。**误报率高的校验器等于没有**，人会直接忽略它。

各来源当前校验结果：
```bash
python3 tools/validate.py apple-docs   # 74 篇：通过 66，8 个真问题
python3 tools/validate.py wwdc         # 10 篇：通过 5，5 个（Resources 链接文字未译）
python3 tools/validate.py blogs        # 18 篇：通过 14，4 个真问题
```

## 八、构建中踩过的坑

完整 15 条见 `README.md` 第六节。最值钱的三条：

1. **「渲染报告零失败」完全不能证明内容没丢**。踩过六次静默失败，全靠体检指标
   （中位正文字数、代码块覆盖率）才发现。最极端的一次：报告成功 29 篇零失败，
   实际每篇只有 23 行、正文全丢。
2. **通用抽取器（trafilatura）会毁代码**：抹平缩进、整个丢失代码块、标题抽成「163 评论」。
   所以 `tools/html2md.py` 自己走 DOM。
3. **httpx 默认连接池等待无上限**：一个请求没释放连接，后续全部永久挂起——
   进程活着、CPU 0%、一页不落，卡了 15 分钟才发现。必须设 pool 超时 + asyncio 硬超时。
