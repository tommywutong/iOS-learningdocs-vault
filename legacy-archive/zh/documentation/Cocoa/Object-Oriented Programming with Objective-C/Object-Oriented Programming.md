# 面向对象编程

身为人类，我们时刻面对着纷繁的事实与印象，必须从中理出头绪。要做到这一点，我们得把底层结构从表面细节中抽象（abstraction）出来，找出真正在起作用的基本关系。抽象能揭示因果、显露模式与框架，把重要的和不重要的区分开。面向对象为你所操作的数据提供了一层抽象；不仅如此，它还把数据和你能对数据执行的操作实实在在地归拢到一起——实际上就是赋予了数据行为。

编程语言历来把世界一分为二——数据，以及作用于数据的操作。数据是静态的、不可变的，除非有操作去改变它。那些作用于数据的过程和函数自身没有持久的状态；它们的价值只体现在能影响数据这一点上。

这种划分当然植根于计算机的工作方式，因此你很难无视它、把它推到一边。就像物质与能量之间、名词与动词之间那种同样无处不在的区分一样，它构成了我们工作的背景。到了某个环节，所有程序员——哪怕是面向对象程序员——都必须把程序要用到的数据结构布置出来，并定义那些作用于数据的函数。

对于 C 这样的过程式编程语言来说，事情基本也就到此为止了。这门语言可能提供各种手段帮你组织数据和函数，但它划分世界的方式不会有什么两样。函数和数据结构就是设计的基本元素。

面向对象编程（object-oriented programming）与其说是在反驳这种世界观，不如说是在更高的层次上重新组织它。它把操作和数据归并成一个个模块化的单元，称为_对象_（object），
 并让你把这些对象组合成结构化的网络，从而构成一个完整的程序。在面向对象编程语言中，对象以及对象之间的交互才是设计的基本元素。

每个对象都同时具有状态（数据）和行为（作用于数据的操作）。在这一点上，它们和普通的实物没多大区别。不难看出，怀表或钢琴这类机械装置既有状态也有行为。但几乎任何为完成某项工作而设计出来的东西也都是如此。哪怕是没有活动部件的简单物件，比如一个普通的瓶子，也把状态（瓶里装了多满、开着还是盖着、里面的东西有多热）和行为（能以不同流速倒出内容物、能被打开或盖上、能承受高温或低温）结合在了一起。

正是这种与真实事物的相似性，赋予了对象大部分的能力与吸引力。它们不但能为现实系统中的部件建模，同样也能作为软件系统中的部件，履行分派给它们的角色。

要创造出程序，你得能够捕捉抽象，并把它们表达在程序设计里。编程语言的职责就是帮你做到这一点。语言应当让你把那些揭示事物运作方式的抽象编码出来，从而促进发明与设计的过程。它应当让你写下的代码把你的想法落到实处。表面细节不该遮蔽你程序的架构。

所有编程语言都提供了帮助表达抽象的手段。这些手段本质上就是把实现细节归拢起来、把它们藏起来，并且至少在一定程度上给它们一个统一的接口——就像一个机械物件把接口和实现分开一样，如图 2-1 所示。

如果你站在内部、以实现者的身份看这样一个单元，你关心的是它由什么构成、如何工作。如果你站在外部、以使用者的身份看它，你关心的只是它是什么、能做什么。你可以越过细节，只从这个单元在更高层次上所扮演的角色去思考。

C 语言中主要的抽象单元是结构体和函数。两者都以各自不同的方式隐藏了实现的某些成分：

- 在世界的数据这一侧，C 的结构体把一个个数据元素归并成更大的单元，之后就能把它当作单个实体来处理。虽然总有些代码必须深入结构体内部、分别摆弄各个字段，但程序的大部分代码可以把它看成单独一个东西——不是一堆元素的集合，而是这些元素合在一起所代表的事物。一个结构体可以包含另一些结构体，因此复杂的信息组织可以由更简单的层次搭建起来。

  在现代 C 中，结构体的字段处在自己的命名空间里——也就是说，它们的名字不会与结构体外部同名的数据元素冲突。要把实现细节挡在接口之外，划分程序的命名空间是必不可少的。不妨想象一下：在一个大型程序里给每一份数据都起一个不重样的名字，还要保证新名字不与旧名字冲突，那将是何等浩大的工程。
- 在世界的过程这一侧，函数把行为封装（encapsulation）起来，使其可以被反复使用而不必重新实现。函数内部的局部数据元素，就像结构体内部的字段一样，在自己的命名空间中受到保护。由于函数可以引用（调用）其他函数，复杂的行为可以由更小的片段搭建起来。

  函数是可复用的。一旦定义好，就可以调用任意多次，而不必再去考虑它的实现。最具通用价值的函数可以收进库里，在许多不同的应用中反复使用。使用者需要的只是函数的接口，而不是源代码。

  不过，与数据元素不同，函数并没有被划分到各自独立的命名空间里。每个函数都必须有唯一的名字。函数本身也许可以复用，它的名字却不能。

C 的结构体和函数能够表达出相当重要的抽象，但它们仍然维持着数据与数据操作之间的区分。在过程式编程语言中，最高层次的抽象单元依然落在“数据”与“操作”这条分界线的某一侧。你所设计的程序，在最高层次上也总要反映计算机的工作方式。

面向对象编程语言并没有丢掉结构体和函数的任何优点——它们更进一步，添加了一种能在更高层次上进行抽象的单元，这种单元把函数与其数据之间的交互隐藏了起来。

举例来说，假设你有一组函数，它们都作用于某个特定的数据结构。你想让这些函数更好用，办法是尽可能把那个结构从接口中拿掉。于是你再补上几个函数来管理这份数据。所有摆弄这个数据结构的活儿——为它分配内存、初始化它、从中取信息、修改其中的值、让它保持最新、释放它的内存——统统通过函数来完成。使用者要做的只是调用这些函数，并把结构传给它们。

经过这些改动，这个结构就变成了一个不透明的令牌，别的程序员根本不需要往里面看。他们可以专注于这些函数做什么，而不必操心数据是怎么组织的。你已经朝着创造一个对象迈出了第一步。

下一步，是让编程语言为这个想法提供支持，把数据结构彻底藏起来，连在函数之间传递都不必了。数据变成了内部的实现细节；导出给使用者的只有一套函数式的接口。因为对象把自己的数据完全封装起来（藏了起来），使用者就可以只从行为的角度来看待它们。

走到这一步，函数的接口已经简单了很多。调用者不需要知道它们是怎么实现的（用了哪些数据）。现在把它称作一个_对象_，已是名副其实。

那个被藏起来的数据结构，把所有共享访问它的函数联结在了一起。所以对象不只是一堆互不相干的函数的集合；它是一束彼此相关的行为，由共享的数据支撑起来。要使用属于某个对象的函数，你先创建这个对象（从而赋予它内部的数据结构），然后告诉这个对象该执行哪个函数。你开始从“对象做什么”的角度去思考，而不再是从一个个孤立的函数的角度。

从思考函数和数据结构，转变为思考对象的行为，这个转变正是学习面向对象编程的精髓所在。一开始它也许让人觉得陌生，但随着你积累起面向对象编程的经验，你会发现这是一种更自然的思考方式。日常编程术语里充满了对现实世界中各类物件的类比——列表、容器、表格、控制器，甚至管理者。把这些东西实现成编程中的对象，不过是把这个类比自然地延伸下去而已。

评判一门编程语言，可以看它让你能编码出哪些抽象。你不该被无关的琐事分散注意力，也不该被迫用一套与你想捕捉的现实并不匹配的词汇来表达自己。

举例来说，如果你必须时时操心让正确的数据与正确的过程配对，那你就被迫始终在很低的实现层次上盯着整个程序。虽然你仍然可以在很高的抽象层次上构思程序，但从想象通往实现的那条路会变得相当脆弱——而且随着程序越来越大、越来越复杂，只会越来越难走。

面向对象编程语言提供了另一个更高的抽象层次，从而给了你更大的词汇量、更丰富的模型来编程。
