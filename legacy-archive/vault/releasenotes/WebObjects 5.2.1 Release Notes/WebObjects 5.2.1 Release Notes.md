| http://www0.info.apple.com/images/box/box-l.gif | ---  |  |  |  |  | | --- | --- | --- | --- | | __TITLE__  WebObjects 5: WebObjects 5.2.1: Update Overview | |  |  | | --- | --- | | Article ID: Created: Modified: | 75433 11/6/02 3/24/03 | |  ---  __TOPIC__   This document contains an overview and download information for Apple's WebObjects 5.2.1 update. Apple recommends that all users of WebObjects 5.2 install this update on all platforms. The [__WebObjects Current Patch List__](http://docs.info.apple.com/article.html?artnum=70037), document 70037, contains information on all available patches and updates for all versions of WebObjects. Read this document if you're not sure which update you need on your system.   ---  __DISCUSSION__   Although WebObjects 5.2.1 resolves some incompatibilities between WebObjects 5.2 and the new Java 1.4.1 implementation for Mac OS X, this configuration has not been formally qualified. We are interested in feedback on WebObjects 5.2 running under Java 1.4.1 and encourage you to file bugs using ([http://bugreport.apple.com](http://bugreport.apple.com)). However, please understand that WebObjects 5.2.x and Java 1.4.1 is not a supported configuration. If you have installed Java 1.4.1 on your Mac OS X (Server) system but would like to use the supported 1.3.1 JVM with your WebObjects applications, please see document 75505 "[__WebObjects 5.2: Using Java 1.3.1 With Mac OS X After Java 1.4.1 Is Installed__](http://docs.info.apple.com/article.html?artnum=75505)". WebObjects 5.2.1 includes updated versions of several WebObjects class and jar files. Some WebObjects project types make copies of these files when the project is built. As a result, some projects may need to be rebuilt to take advantage of the issues addressed in the update. For example, when a JSP/Servlet war archive is created, several jars are copied into the war file. At least one jar (WOJSPServlet_client.jar, from the WOJSPServlet.framework) is always copied, and additional framework jars may be copied into the war as well, depending on the project. After installing WebObjects 5.2.1, either the application must be rebuilt (recreating the war archive), or the war archive must be manually updated, using the jar tool. This update includes modified WebObjects client-side Java classes and jars. On Mac OS X Server and Microsoft Windows the update installer automatically places the modified classes and jars in your web server's document root directory. On Sun Solaris, the update installer places the modified classes in the WebObjects installation (in NEXT_ROOT/Library/WebObjects/WODocumentRoot/WebObjects) but does not copy them to your web server's document root directory. To use the new files, you must install them in the correct location for the web server being used. __WebObjects 5.2.1 for Mac OS X (Server) 10.2.4__  __Important__: There are two mutually exclusive updates for this platform. If you have WebObjects 5.2 Developer installed on Mac OS X 10.2.4, you need the WebObjects 5.2.1 Developer update. If you have WebObjects 5.2 Deployment installed on Mac OS X Server 10.2.4, you need the WebObjects 5.2.1 Deployment update. You do not need both on any system. This update is available through the Software Update feature of Mac OS X. If you use this method, only the proper update for the software which you have installed on your system is visible and available for download. If you prefer to download and install the package manually, follow the instructions below. __Note__: __WebObjects 5.2.1 Deployment__ requires:  - Mac OS X Server 10.2.4 or later    __WebObjects 5.2.____1__ __Developer__ requires:  - Mac OS X 10.2.4 or later- December 2002 Mac OS X Developer Tools    If you have not yet updated to the correct version of Mac OS X (Server) or Developer Tools, you must do so before installing WebObjects 5.2.1. Mac OS X 10.2.4 is available through Software Update and the December 2002 Mac OS X Developer Tools image is available on the Apple Developer Connection web site at: ([http://www.apple.com/developer](http://www.apple.com/developer)). RESOLUTION: This issue has been corrected. __WebServices Generation needs to handle abstract entities better__ Apple Reference 3087212 ISSUE: Direct To Web Services generated incorrect serialization and update operations for abstract entities. RESOLUTION: This issue has been corrected. __When using WOHost on a machine with multiple IP's, instances cannot be controlled by Monitor__ Apple Reference 3094168    ISSUE: In previous releases of WebObjects (5.0 and 5.1), a developer could use WOHost to bind applications to a specific IP address on a multi-IP machine. In many cases applications could not be deployed with Monitor without using this option. In WebObjects 5.2, the -WOHost flag to wotaskd is not respected properly by computers with multiple IP addresses, and therefore Monitor/wotaskd will be unable to manage the applications. RESOLUTION: This issue has been corrected. __Project Builder displays \*.api file instead of \*.html file__ Apple Reference 3096792 ISSUE: When a new WebObjects component was created, Project Builder opened the \*.api file, which usually wasn't what the user wanted. RESOLUTION: The \*.html file is now opened by default when a new WebObjects component is created in Project Builder. __WOFileUpload streamToFilePath does not work with multipleSubmit enabled__ Apple Reference 3100655 ISSUE: When a WOFileUpdload component with a streamToFilePath binding is in a WOForm with multipleSubmit enabled, the submit action will not work. RESOLUTION: This issue has been corrected. __NSTimestamp getTime() returned incorrect values in JVM 1.4.1__ Apple Reference 3108013 ISSUE: In Java Virtual Machine 1.3.1 __java.sql.Timestamp.getTime()__ returns only integral seconds. In Java Virtual Machine 1.4.1 __java.sql.Timestamp.getTime()__ returns not only integral seconds but also milliseconds. This change in behavior between the JVMs caused the WebObjects 5.2 implementation of __NSTimestamp__ to return incorrect values when running in a 1.4.1 JVM. RESOLUTION: This issue has been corrected. __Deploying 5.2 apps as servlets with invalid license key__ Apple Reference 3108021 ISSUE: Starting up a WebObjects 5.2 application in a servlet container on a system with an invalid license key could potentially bring down the JVM. RESOLUTION: This issue has been corrected. __Fault handlers need to lock__ Apple Reference 3108093 ISSUE: Some of the fault handlers in the EOAccess framework were not locking properly and causing missing lock warnings to be thrown. RESOLUTION: This issue has been corrected. __New EO gets nulled when put in a child editing context of the original editing context__ Apple Reference 3108102 ISSUE: If you called __EOUtilities.localinstanceOfObject()__ with a child editing context and an EO that was in the parent editing context, you would get a null value returned. RESOLUTION: This issue has been corrected. __NSTimestampFormatter cannot parse format starting with "%Z" in 1.4.1 JVM__ Apple Reference 3119393 ISSUE: When running in a 1.4.1 JVM, the __NSTimestampFormatter__ method parseObject could not parse a string generated by its own format method using any format strings ending with "%Z" or "%z". RESOLUTION: This issue has been corrected. __New project folder not created properly__ Apple Reference 3122965 ISSUE: When using the Mac OS X December 2002 Developer Tools with WebObjects 5.2, the project folder was not created properly when a new WebObjects project was created. RESOLUTION: This issue has been corrected. __WOEventDisplay page broken__ Apple Reference 3130956    ISSUE: Attempting to enable WOEvents and view the WOEventDisplayPage resulted in a ClassCastException. RESOLUTION: This issue has been corrected. __canSetValueForBinding incorrectly returns false__ Apple Reference 3130996 ISSUE: The WOComponent method canSetValueForBinding was returning false in some cases where the value for the binding could be set. RESOLUTION: This issue has been corrected. __NullPointerException in EOEditingContext._eoForGID()__ Apple Reference 3132579 ISSUE: There were potential causes of null pointer exceptions in the __EOEditingContext._eoforGID()__ method. RESOLUTION: This issue has been corrected. __NullPointerException when faulting array fault into child editing context which contains deleted object__ Apple Reference 3133313    ISSUE: A __NullPointerException__ could be thrown when faulting in a relationship from a parent to a child editing context if the parent's relationship contained a newly inserted object that had been deleted. RESOLUTION: This issue has been corrected. __Uploading files with zero content length using a form coded with "multipart/form-data" throws exception__ Apple Reference 3145389 ISSUE: Certain browsers reported an incorrect content length when uploading files with zero content length, which caused WebObjects to throw an exception. RESOLUTION: This issue has been corrected. __Extra sessions created with certain browsers in direct connect mode__ Apple Reference 3145517 ISSUE: Many browsers now send a request for a favicon.ico file. WebObjects could not handle the mime type "ico" = "text/plain" correctly, which resulted in an extra session being created for each of these requests. RESOLUTION: This issue has been corrected. __WOWebServices cannot handle UTF-8 data__ Apple Reference 3147624    ISSUE: WOWebServices crashed with an AXIS or SOAP fault when working with UTF-8 encoded strings. RESOLUTION: WOServiceUtilities in the JavaWebServicesGeneration framework no longer uses the EOF qualifier parser. The workaround described in Knowledge Base document 75490 "[__WebObjects 5.2: UTF-8 Exception in WebObjects Web Services__](http://docs.info.apple.com/article.html?artnum=75490)" is also necessary for WebObjects web services servers to handle UTF-8 encoded strings. __FileUpload with malformed headers could cause large CPU usage__ Apple Reference 3149051 ISSUE: Certain HTTP Requests with malformed headers could cause the WebObjects request handlers to take up all CPU cycles. RESOLUTION: This issue has been corrected. __Deadlock when a Direct Action raises an exception__ Apple Reference 3149140 ISSUE: If a Direct Action loads a session, then throws an exception, the WebObjects application stops responding ("hangs") the next time that same session is accessed. RESOLUTION: This issue has been corrected. __bytesForResourceNamed did not support nested resources__ Apple Reference 3152708 ISSUE: The WOResourceManager method __bytesForResourceNamed__ took a resource name rather than a path to the resource, which did not allow access to nested resources. RESOLUTION: To discourage using String path, Apple did not enhance the method __bytesForResourceNamed__ to accept a path to the resource. Instead 2 new methods were introduced. This resulted in stale data in the shared context. RESOLUTION: This issue has been corrected. __Nested compound primary keys sometimes generate null values__ Apple Reference 3158036 ISSUE: Under some circumstances, null values are generated by EOF for nested compound primary keys. RESOLUTION: We have provided a fix for some of the customer reported scenarios we have received in bug reports. __Rapid development sometimes fails with PB__ Apple Reference 3162235    ISSUE: If you developed your application with Project Builder, used a separate build projects directory, and that directory was a symbolic link to another location, rapid development sometimes failed to work. RESOLUTION: This issue has been corrected. __ArrayIndexOutOfBoundsException in WOObjectPool.resize()__ Apple Reference 3171503 ISSUE: WOObjectPool could not grow beyond 50% of its maximum permitted size without throwing an __ArrayIndexOutOfBoundsException__.
