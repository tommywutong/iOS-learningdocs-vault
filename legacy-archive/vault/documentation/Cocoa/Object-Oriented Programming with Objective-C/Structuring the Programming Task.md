# 组织编程任务

面向对象编程不仅能把程序组织得更好，还有助于组织编程这项工作本身。

随着软件想做的事情越来越多，程序越来越大、越来越复杂，管理这项工作的难度也随之上升。要拼合的部件更多了，一起构建这些部件的人也更多了。面向对象的方式提供了应对这种复杂性的办法——不只是在设计上，也在工作的组织上。

复杂的软件需要一群人展开非同寻常的协作：每个人都必须各自发挥创造力，同时又要让自己做出的东西与别人做的严丝合缝。

工作量之大，加上同一时间、同一地点参与同一项目的人数之多，本身就可能妨碍这个群体朝共同目标协同工作的能力。此外，协作还常常受到时间、空间和组织上的阻隔：

- 代码写完之后还要长期维护、改进和使用。在同一个项目上协作的程序员未必处在同一时期，因此他们可能没有机会互相商量，也没法让彼此了解实现的细节。
- 即使程序员在同一时期做同一个项目，他们也可能不在同一个地方。这同样会限制他们能配合到多紧密。
- 在不同小组工作、优先级不同、排期不同的程序员，也常常必须在项目上协作。跨越组织壁垒的沟通并不总是容易实现。

解决这些困难的办法，必须从程序设计和编写的方式中生长出来。它不能以层层管理结构和严格权限等级的形式从外部强加。那些东西往往会妨碍人的创造力，其本身还会变成负担。相反，协作必须内建到工作本身之中。

这正是面向对象编程技术能帮上忙的地方。举例来说，面向对象代码的可复用性意味着：程序员即使在不同时期做不同的项目，或者身处不同的组织，只要通过库共享代码，也能有效地协作。这种协作大有可为，因为它有望减轻艰巨的任务，让看似不可能的项目变得可行。

面向对象编程有助于重塑编程任务，让它更有利于协作。它有助于消除在底层实现细节上协作的必要，同时提供了便于在更高层次上协作的结构。对象模型的几乎每一项特性——从大规模设计的可能性，到代码复用性的提升——都会影响人们协同工作的方式。

程序如果是在高抽象层次上设计的，分工也就更容易构想。分工可以与程序在逻辑上的划分对应起来；一个项目的组织方式可以从它的设计中自然生长出来。

有了面向对象的设计，共同目标更容易被始终看在眼里，而不至于淹没在实现之中；每个人也更容易看清自己手上这一块如何嵌入整体。因此，他们的协作更有可能不跑偏。

面向对象程序各个部件之间的连接，在设计过程的早期就理清了。至少就开发的初始阶段而言，它们可以在实现开始之前就被明确定义好。

在实现阶段，只有这层接口需要协调，而其中大部分本来就是设计的自然产物。因为每个类都封装了自己的实现，并拥有自己的命名空间，所以不需要协调实现细节。需要协调的地方越少，协作就越简单。

面向对象编程的模块化意味着，一个大程序的各个逻辑部件可以分别实现。不同的人可以负责不同的类。每项实现任务都与其他任务相互隔离。

模块化的好处不只体现在组织实现工作上，也体现在日后排查问题上。因为实现被约束在类的边界之内，冒出来的问题也很可能是被隔离开的。当 bug 位于程序中一个界定明确的部分时，追查起来更容易。

按类分离职责还意味着，每一部分都可以交给专门的人去做。类可以定期更新，以优化性能、用上新技术。这些更新不必与程序的其他部分协调。只要对象的接口不变，对其实现的改进可以安排在任何时候。

面向对象程序的多态带来了更简单的编程接口，因为同样的名字和约定可以在任意多个类中复用。结果就是要学的东西更少，大家对整个系统如何运作有更多共同的理解，通向配合与协作的路也更平坦。

因为面向对象程序在运行时动态做决定，要让两段代码协同工作，需要在编译期（也就是在源代码中）提供的信息就更少。于是要协调的地方更少，会出岔子的地方也更少。

继承是复用代码的一种方式。如果你能把自己的类定义成更通用的类的特化版本，你的编程任务就简化了。设计同样得到简化，因为继承层级把不同实现层次之间的关系摆了出来，让它们更容易理解。

继承还提升了代码的复用性和可靠性。放在超类里的代码会被它的子类检验。你在库里找到的那个通用类，早已经受过其他子类的检验——那些子类是别的开发者为别的应用写的。

你能从别人那里借用、并纳入自己程序的软件越多，你自己要做的就越少。在面向对象编程环境里可供借用的软件更多，因为代码的复用性更高。程序员即便身处不同地方、为不同组织工作，彼此的协作也因此得到加强，而每个项目的负担则得以减轻。

来自面向对象库的类和框架，可以为你的程序做出实质性的贡献。举例来说，当你使用 Apple 提供的软件框架编程时，你实际上是在与 Apple 的程序员协作；你把程序的一部分（往往是相当大的一部分）交给了他们去承担。你可以专注于自己最擅长的事，把其他任务留给库的开发者。你的项目能更快做出原型、更快完成，而你自己这边的协作压力也更小。

面向对象代码复用性的提升，也提升了它的可靠性。从库里取来的类，多半已经进入过各种各样的应用和场景。代码被用得越多，问题被遇到并修复的可能性就越大。那些在你程序里看起来诡异、难以定位的 bug，也许早就被追查出来并消灭掉了。
