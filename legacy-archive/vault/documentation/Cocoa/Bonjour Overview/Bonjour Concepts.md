# Bonjour 概念

Bonjour 是一套基于 IP 的零配置联网协议，Apple 已将其提交给 IETF，作为标准制定工作的一部分。本节介绍 Bonjour 要解决的问题，以及它是如何解决这些问题的。

在过去二十年里，计算机逐步从 AppleTalk、IPX、NetBIOS 这类平台专有协议转向了互联网协议（IP）。如今绝大多数计算机和其他网络设备都使用 TCP/IP 通信。然而在这一转变过程中，有一项功能丢失了——把设备接入本地网络后，网络上的计算机和其他设备几乎不需要任何配置就能连接到这些设备。

要让 IP 正常工作，每台设备都需要一个唯一的地址，可以是静态指定的，也可以是由 DHCP 服务器动态分配的。动态分配的地址会变化，因此在没有 Bonjour 的年代，打印机和其他设备必须手动配置成静态地址，网络上的计算机才能访问到它们。然后，网络管理员还得配置一台 DNS 服务器，这样计算机用户才不必用 IP 地址去连接打印机。于是，一件看似不起眼的小事却需要大量配置工作。而现实中架设网络的往往并不是传统意义上的网络管理员——比如一家人通过共享路由器把笔记本电脑接入互联网——对他们来说，这种程度的配置根本不现实。

即便是在 IT 专业人员管理的网络中，要求对打印机之类的设备做手动配置也毫无道理。人们期望的是插上打印机、把两台笔记本电脑连起来，或者在本地网络上找一台文件服务器或游戏服务器，而不必浪费时间去折腾配置是否正确。

要做到这一点，人们需要一种简单可靠的方式来配置和浏览 IP 网络上的服务。他们希望能发现可用的服务并从列表中选一个，而不必事先知道每个服务的名称或 IP 地址。让 IP 具备这种能力符合所有人的利益。而这正是 Bonjour 所提供的能力。

零配置 IP 联网蕴含着巨大的潜力。以日常的打印任务为例。一旦在你的电脑或 iOS 设备上配置好打印机，接下来只需在应用程序里选择"打印"命令即可。

把笔记本电脑带到客户公司或邻居家里，试着打印点东西。如果他们的打印机支持 Bonjour 协议，打印会和在你自己的本地网络上一样简单。要打印时，把笔记本电脑连到客户的 Wi-Fi 接入点并开机；或者开机后笔记本立刻找到了邻居家的无线网络。无论哪种方式，你的笔记本电脑都会自动发现所有可用的打印机。你打开文档，选择"打印"命令，所有可用的打印机都会出现在打印对话框中。你选中一台打印机，点击"打印"，文档就打印出来了。

再比如你想和朋友玩一局联机游戏。你打开游戏，朋友那份游戏立刻就能在网络上看到你这一份。或者你在两台电脑上都装了音乐分享应用，这两个程序自己就能互相发现，并立即交换歌曲列表。同样地，如果你有一个共享文件夹，或者打开了个人 Web 共享，你的共享文件和网页会立刻对他人可用。

[图 1-1](#apple-f4xwc4dqnrsv64tfmyxwi33df52wszbpkridimbqgazdinjyfvjvomy) 描绘了这个场景。第 1 步，你在邻居家打开笔记本电脑，笔记本要么从路由器里的 DHCP 服务器获得一个地址，要么在没有 DHCP 服务器的情况下自行指定一个可用的本地地址。第 2 步，系统在网络上查询可用的打印机，于是你打开打印对话框时，邻居家的打印机就列在其中。最后第 3 步，你在自己的电脑上打开音乐分享，邻居的电脑发现了它并建立连接。

这些只是能从零配置 IP 联网中受益的现有应用中的少数几个例子。零配置 IP 联网有潜力改善移动游戏、家庭内联网、分布式计算以及其他许多网络应用。此外，零配置 IP 联网还为一整类全新的 IP 数字设备打开了大门。

!

Bonjour 是 Apple 为基于 IP 的零配置联网提出的方案。Bonjour 源自 ZEROCONF 工作组的成果，该工作组隶属于互联网工程任务组（IETF）。ZEROCONF 工作组针对基于 IP 的零配置联网提出的需求与解决方案，基本涵盖三个方面：

- 编址（为主机分配 IP 地址）
- 命名（用名称而不是 IP 地址来指代主机）
- 服务发现（自动找到网络上的服务）

Bonjour 为这三个方面都提供了零配置的解决方案，具体见接下来的四个小节。

Bonjour 让服务提供商、硬件厂商和应用程序开发者只需支持单一的网络协议——IP——就能在易用性上开创新局面。

网络用户再也不必指定 IP 地址、指定主机名，甚至不用输入名称就能访问网络上的服务。用户只需要求查看有哪些网络服务可用，然后从列表里挑一个即可。

在很多方面，这种浏览方式对应用程序比对用户更有价值。应用程序可以自动探测到自己需要的服务或可以与之交互的其他应用程序，从而在无需用户干预的情况下自动完成连接、通信和数据交换。

编址问题由自行指定的链路本地地址解决。链路本地编址使用一段为本地网络（通常是小型 LAN 或单个 LAN 网段）保留的地址范围。为此，IPv6 规范已把自行指定链路本地地址纳入协议本身。零配置联网在编址方面的主要挑战，是如何把这种能力补装到 IPv4 上。

在 IPv4 中，自行指定地址的做法是：在链路本地范围内随机挑一个 IP 地址并测试它。如果该地址未被占用，它就成为你的本地地址；如果已被占用，计算机或其他设备就再随机挑一个地址重试。

IPv4 和 IPv6 的链路本地编址在大多数主流操作系统上都得到支持。硬件厂商应当在自己的设备上实现链路本地编址，才能充分享受 Bonjour 带来的好处。

在支持链路本地编址的计算机或 iOS 设备上，任何用户或服务都会自动从该特性中受益。当你的主机接入一个本地网络时，它会找到一个未被占用的本地地址并采用它。你无需做任何操作。

在本地网络上，名称到地址转换的解决方案采用多播 DNS（mDNS）：DNS 格式的查询通过 IP 多播在本地网络上发送。由于这些 DNS 查询发往一个多播地址，因此不需要某台掌握全局信息的 DNS 服务器来应答查询。每个服务或设备都可以自行提供 DNS 能力——当它看到针对自己名称的查询时，就用自己的地址给出 DNS 响应。

Bonjour 还更进一步。它内含一个响应程序，负责处理针对主机或 iOS 设备上任何网络服务的 mDNS 查询。这样一来，你的应用程序就不必自己解析和响应 mDNS 消息。只要注册你的服务，Bonjour 的 mDNSResponder 守护进程就会自动通告该服务的可用性，使得针对你的名称的任何查询都会被自动导向正确的 IP 地址和端口号。

Bonjour 还内置支持 NAT 端口映射协议（NAT-PMP）。如果上游路由器支持该协议，OS X 和 iOS 应用就可以创建和销毁端口映射，让防火墙另一侧的主机能连接到你提供的服务。（关于 NAT 端口映射的更多说明，见 _[Networking Overview](../../Networking%20Internet%20Web/Networking%20Overview/About%20Networking.md#apple-f4xwc4dqnrsv64tfmyxwi33df52wszbpkridimbqgeydemrq)_ 中的 [Firewalls and Network Address Translation](../../Networking%20Internet/Networking%20Concepts/Packet%20Routing%20and%20Delivery.md#apple-f4xwc4dqnrsv64tfmyxwi33df52wszbpkridimbqgezdiobxfvbuqmjrfvjvomq)。）

要让名称到地址的转换正常工作，本地网络上需要有一个唯一的名称。与传统的 DNS 主机名不同，本地名称只在本地网络或 LAN 网段内有意义。你可以像自行指定本地地址那样自行指定本地名称——挑一个；只要还没被占用，它就归你了：

- 硬件厂商判断所选名称是否已被占用的做法是：让设备发出针对该名称的 mDNS 查询，看是否有响应。如果有响应，设备就应另选一个名称。没有用户界面的设备会在默认名称后追加一个递增的数字，直到名称唯一为止。例如，一台默认名称为 `XYZ-LaserPrinter.local` 的打印机接入一个已经装有两台同型号打印机的本地网络时，它会先测试 `XYZ-LaserPrinter.local`，再测试 `XYZ-LaserPrinter-2.local`，然后是 `XYZ-LaserPrinter-3.local`——这个名称未被占用，于是成为它的名称。
- 软件服务在向 Bonjour 注册时提供一个名称。如果所提供的名称已被占用，默认情况下 Bonjour 会自动为你的服务改名。

在 OS X 中，用户可以通过"系统偏好设置"的"共享"面板中的"本地主机名"设置为自己的电脑设定主机名。（在 iOS 中，主机名是自动生成的，不可配置。）这个主机名可以用在任何使用传统 DNS 主机名的地方——Web 浏览器、命令行工具等等。要告诉系统某个名称是本地主机名，就在主机名后面追加一个点（`.`）和 `local.`；`Steve.local.` 就是一个本地主机名的例子。

例如，如果用户在 Web 浏览器里输入 `steve.local.`，这就告诉系统在本地网络上多播针对 `steve` 的请求，而不是把它发给传统的 DNS 服务器。如果本地网络上有一台名为 `steve` 的启用了 Bonjour 的计算机，用户的浏览器就会收到它的正确 IP 地址。这让用户无需传统 DNS 服务器就能访问本地主机和服务。

更多信息请参阅[域名命名约定](Domain%20Naming%20Conventions.md#apple-f4xwc4dqnrsv64tfmyxwi33df52wszbpkridimbqgazdinrqfvjvomi)。

Bonjour 的最后一个要素是服务发现。服务发现让应用程序能找到某一类服务的所有可用实例，并维护一份服务名称与端口号的列表。随后，应用程序可以把服务的主机名解析成一组 IPv4 和 IPv6 地址，见[命名](#apple-f4xwc4dqnrsv64tfmyxwi33df52wszbpgiydambrga3teljrhe4damrx)一节。

这份服务名称列表在服务与其当前的 DNS 名称和端口号之间提供了一层间接性。有了这层间接性，应用程序可以持久保存一份可用服务的列表，并在真正要使用某个服务之前才去解析实际的网络地址。这份列表还使得服务可以动态迁移位置，而不会因为公告变更而产生大量网络流量。

Bonjour 中的服务发现是通过"浏览"完成的。系统针对给定的服务类型和域发出一个 mDNS 查询，所有匹配的服务都用自己的名称作答。最终得到的就是一份可供选择的可用服务列表。

这与传统上以设备为中心的网络服务观念大相径庭。对于打交道的对象是服务器、网络设备和网络编程的人来说，很容易养成从物理硬件角度思考服务的习惯。在这种以设备为中心的视角下，网络由若干设备或主机组成，每台各自提供一组服务。例如，网络可能由一台服务器和若干客户机构成。在以设备为中心的浏览方案里，客户端向服务器查询它正在运行哪些服务，取回一份列表（FTP、HTTP 等等），再决定使用哪个服务。界面反映的是物理系统的组织方式，但这未必是用户在逻辑上想要或需要的东西。

用户通常想完成某项具体任务，而不是去查询一堆设备、弄清它们各自在跑什么服务。让客户端只问一个问题——"有哪些打印服务可用？"——远比向每台可用设备逐一发问"你在运行哪些服务？"然后从结果中筛出打印机要合理得多。以设备为中心的做法不仅耗时，还会产生大量网络流量，其中绝大部分毫无用处。而以服务为中心的做法只发出一次查询，只引来相关的应答。

此外，服务并不绑定在特定的 IP 地址上，甚至不绑定在主机名上。例如，一个网站可能由多台地址不同的服务器托管。在一家机构内部，网络管理员可能需要把某个服务从一台服务器迁到另一台以均衡负载。如果客户端保存的是主机名（现实中大多数情况正是如此），那么服务一旦迁到别的主机，客户端就连不上了。

Bonjour 采用的是面向服务的视角。查询依据的是所需的服务类型，而不是提供服务的主机。应用程序保存的是服务实例名，而不是地址，因此即使 IP 地址、端口号乃至主机名发生变化，应用程序仍然能连上。通过聚焦服务而非设备，用户的浏览体验变得更实用、更省心。

无服务器的编址、命名和服务发现有可能带来大量多余的网络流量，但 Bonjour 采取了若干措施把这类流量降到最低。这让 Bonjour 既能达到 AppleTalk 那样的易用性，又能避免不必要的"喋喋不休"。

Bonjour 采用多种机制来降低零配置的开销，包括缓存、抑制重复响应、指数退避和服务公告，具体见以下各节。

Bonjour 使用多播 DNS 记录的缓存，避免主机重复请求已经请求过的信息。例如，当某台主机请求（比方说）一份 LPR 打印后台处理程序列表时，打印机列表是通过多播返回的，因此所有本地主机都能看到。下次某台主机需要打印后台处理程序列表时，它的缓存里已经有这份列表了，不必再发一次查询。缓存的维护由多播 DNS 响应程序负责，应用程序开发者无需为维护缓存做任何事情。

为避免同一查询被反复应答，Bonjour 的服务查询中会带上一份已知答案列表。例如，如果某台主机正在浏览打印机，第一次查询不包含任何打印服务，于是（比方说）收到了十二个可用打印服务器的回复。该主机下次查询打印服务时，查询中就会带上已知服务器的列表。已经在列表上的打印服务器不会再作答。

Bonjour 还以另一种方式抑制重复响应。如果某台主机正准备作答，却发现另一台主机已经用相同的信息响应过了，它就会抑制自己的响应。

应用程序开发者无需为抑制重复响应做任何事情，Bonjour 会处理重复响应的抑制。

主机在浏览服务时，并不会持续不断地发送查询来看是否有新服务出现。相反，主机先发出一次初始查询，之后各次查询的间隔按指数增长，例如：1 秒后、3 秒后、9 秒后、27 秒后，依此类推，最长间隔为一小时。

这并不意味着浏览器要一个多小时才能看到新服务。当某个服务在网络上启动时，它会用类似的指数退避算法把自己的存在公告若干次。这样一来，用于服务公告和发现的网络流量被压到最低，而新服务仍然能被很快看到。

在配备 Bonjour 的主机上运行的服务，在向 mDNSResponder 守护进程注册时会被自动公告。运行在其他硬件（例如打印机）上的服务，则应当自行实现带指数退避的服务公告，以充分发挥 Bonjour 的作用。
