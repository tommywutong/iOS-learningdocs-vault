| |  |  |  |  |  |  | | --- | --- | --- | --- | --- | --- | | |  | | --- | | images/tnmenutop.gif | | CONTENTS | | [The Symptoms](#)    [The Problem](#)    [The Solutions](#)    [Summary](#)   [References](#)   [Change History](#)   [Downloadables](#) | | images/tnmenubottom.gif | | Recently, Apple became aware of problems in Mac OS and in third-party code which can cause a crash.  The problem occurs when a program inadvertently unlocks one or more [QuickDraw](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-284.html) data structures. The crash typically occurs elsewhere, when the system accesses one of these data structures under the assumption that it is locked.  This Technote is addressed to two audiences: developers whose products make any use of the [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) data structure, and users who seek more information on certain intermittent crashes reported in other media.   Updated: [Jun 15 1998] |       ---     The Symptoms The problem manifests most often as a crash in [`StdText`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-180.html#HEADING180-0) (MacsBug reports the crash in `NQDStdText`, which is the PowerPC version of [`StdText`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-180.html#HEADING180-0)). The crash occurs when a half-dereferenced [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) is accessed after a call which can (and does) move memory.  It should be noted that a crash could theoretically appear in a number of places as a result of the problem. The problem generally does not occur near the site of the crash. One of the more insidious potential examples of this is in the cursor drawing routines, which are executed at interrupt time. An unlocked [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) could be accessed while it is being moved by the [Memory Manager](https://developer.apple.com/documentation/mac/Memory/Memory-56.html#HEADING56-0), although this is considered a rare, if at all extant, symptom.   [Back to top](#) The Problem [`NewGDevice`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-279.html#HEADING279-0) locks a [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) immediately after creating it, and the rest of [QuickDraw](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-2.html) assumes it will stay locked. The problem is that some programs, including numerous third-party applications and some versions of Apple's Monitors & Sound control panel (including the version in Mac OS 8) contain code like this:     |  | | --- | | ```     // begin problematic code    GDHandle gdh = GetMainDevice ( );    HLock ((Handle)gdh);    // do something with or to gdh    // which moves memory (requires gdh to be locked)    HUnlock ((Handle)gdh);    // this is the problem line    // end problematic code ``` |     The above code assumes that the [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) is unlocked before the code executes, and unlocks it as the code ends. (Ironically, there was never any need to lock this [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html).)     |  | | --- | | __Note:__  Versions of Monitors & Sound which shipped in Mac OS 8.1 and later do not have this problem.  There has always been a requirement that a [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) in the [system's graphic device list](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-284.html) remain locked. The requirement is present in the first-released implementation of [Color QuickDraw](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-197.html) (the Mac II ROMs) and the original source code contains comments to the effect that a [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) in the [system's graphic device list](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-284.html) must never be unlocked.  Thus, the potential for the problem has always been present, though the symptoms have only recently been isolated. Because of the complex way in which relocatable [Memory Manager](https://developer.apple.com/documentation/mac/Memory/Memory-56.html#HEADING56-0) blocks move over time, programs which cause the problem have not necessarily also caused the symptoms, and when they have caused the symptoms, the symptoms have not always been easily reproducible. (The offending programs have been "getting away with it.")  An exhaustive search of Apple's previous documentation turned up no instances of explicit prohibitions against unlocking a [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) in the [system's graphic device list](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-284.html). Informally communicated Mac OS programming lore has always held that you should be careful when changing the state of a handle not created by your own code. We are now making this rule formal and explicit. (See the [Developer Solution](#) section, below, for details.) |       [Back to top](#) The Solutions The previous version of this Technote claimed there would be a solution which users could apply. In fact, there is only a developer solution. Developer Solution You should make sure none of your code unlocks a [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) in the [system's graphic device list](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-284.html). Use code like the following if you need to make sure a [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) is locked while you access it:     |  | | --- | | ``` GDHandle gdh = GetMainDevice ( ); SInt8 hState = HGetState ((Handle) gdh);    HLock ((Handle)gdh);     // do something with or to gdh     // which moves memory (requires gdh to be locked)    HSetState ((Handle)gdh,hState); ``` |     This code saves the handle's state, locks the handle, and restores the handle's previous state. This means that if the handle is locked before this code runs, it will stay locked afterward, and if the handle is unlocked before this code runs, it will be unlocked afterward.  In a perfect world, you would not need to lock or unlock any [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html), because it would always be locked before your program ever saw it. However, the possibility that other programs may erroneously unlock a [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) in the [system's graphic device list](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-284.html) is real. The above code shows one proper way to protect yourself from that possibility.  Another technique would be to avoid locking a [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) entirely and, instead, copy its fields into local variables as necessary. Most fields of the [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) are small and should not be inconvenient to copy.  Apple has not found any cases in which you need to keep any [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) which is __not__ in the [system's graphic device list](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-284.html) locked. For example, a [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) created by [`NewGWorld`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-311.html#HEADING311-0) is unlocked.  If your program needs to lock any [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html), the easiest and safest thing to do is save and restore the state of the [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) in order to work properly, regardless of whether the [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) is in the [system's graphic device list](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-284.html).     |  | | --- | | __Note:__  This solution does not solve the problem completely with respect to binaries that have already been deployed. If a [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) is ever unlocked by an existing binary program, the potential for a crash begins immediately because system code, such as `NQDStdText`, will not be altered to lock a [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) before accessing it. This solution only keeps new programs from causing the problem and keeps them from crashing if they ever encounter an unexpectedly unlocked [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) in the [system's graphic device list](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-284.html). The system, however, may still crash when it encounters such a [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html).  An exhaustive search of Apple's previous documentation produced no clear directions for when to use [`HUnlock`](https://developer.apple.com/documentation/mac/Memory/Memory-89.html#HEADING89-0) and when to use [`HGetState`](https://developer.apple.com/documentation/mac/Memory/Memory-86.html#HEADING86-0) and [`HSetState`](https://developer.apple.com/documentation/mac/Memory/Memory-87.html#HEADING87-0). As a result, DTS has produced a [separate Technote](../Locking%20and%20Unlocking%20Handles/tn1122.md) treating this issue in detail. |    User Solution The previous version of this Technote claimed Apple would be releasing a system extension that masks this problem. Since this Technote's publication, however, Apple has chosen not to release this extension.   [Back to top](#) Summary No [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) in the [system's graphic device list](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-284.html) should ever be unlocked. Some programs, both from Apple and from third parties, unlock at least one [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) in the [system's graphic device list](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-284.html). This can cause a crash. Developers should preserve the state of any [`GDHandle`](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-275.html) in the [system's graphic device list](https://developer.apple.com/documentation/mac/QuickDraw/QuickDraw-284.html), which needs to be locked by calling [`HGetState`](https://developer.apple.com/documentation/mac/Memory/Memory-86.html#HEADING86-0) and [`HSetState`](https://developer.apple.com/documentation/mac/Memory/Memory-87.html#HEADING87-0). There is no solution users can apply.
