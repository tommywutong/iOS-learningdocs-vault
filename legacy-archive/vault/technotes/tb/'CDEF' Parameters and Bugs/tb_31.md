| |  |  |  |  |  |  | | --- | --- | --- | --- | --- | --- | | |  | | --- | | images/tnmenutop.gif | | 目录 | | [简介](#)   [drawCntl (0) and autoTrack (8)](#)   [posCntl (5) and thumbCntl (6)](#)   [_TrackControl](#)   [参考资料](#)   [可下载资源](#) | | images/tnmenubottom.gif | | 本技术笔记描述了控制管理器（Control Manager）中影响控件定义函数（`'CDEF'` 资源）的一些已知问题。  [1988 年 8 月 1 日] |       ---      简介 _Inside Macintosh_ 第 I-309 卷的控制管理器一章介绍了如何编写控件定义函数（`'CDEF'` 资源）。本笔记假定你已基本理解该章内容，尤其是通过 `message` 参数发送的各种消息。  [返回顶部](#) drawCntl (0) and autoTrack (8) 当 `'CDEF'` 以 `drawCntl` 或 `autoTrack` 消息被调用时，`param` 参数的高位字（high word）可能包含未定义的数据，这可能导致依赖 `param` 全部 32 位均已定义的例程出错。`'CDEF'` 资源在处理 `drawCntl` 和 `autoTrack` 消息时，应当只考虑 `param` 参数的低位字（low word）。  [返回顶部](#) posCntl (5) and thumbCntl (6) 根据 _Inside Macintosh_ 的说明，只有当应用程序对指示器（滑块，thumb）进行自定义拖动时，控制管理器才会以 `posCntl` 消息和 `thumbCntl` 消息调用 `'CDEF'`，而在默认拖动时则不会。这并不属实。实际情况恰好相反：当应用程序进行默认拖动时，控制管理器才会以 `posCntl` 消息调用 `'CDEF'`。而无论应用程序采用哪种拖动方式，`'CDEF'` 都会收到 `thumbCntl` 消息，只不过其返回结果只在默认拖动时才会被采用（自定义拖动时会被忽略）。  [返回顶部](#) _TrackControl 当用户点按你的控件时，你通常会调用 `_TrackControl`，它在用户没有改变控件设置时应返回零，在用户改变了控件设置时则应返回对应的部件代码（part code）。但对于实现了自定义拖动的 `'CDEF'` 资源，无论用户是否改变了控件设置，`_TrackControl` 都会返回零。要绕开这个问题，你必须用其他方法来判断用户是否改变了控件设置，例如在调用 `_TrackControl` 前后比较控件的值。  [返回顶部](#) 参考资料 _Inside Macintosh_ 第 I-309 卷，控制管理器  [返回顶部](#) 可下载资源  |  |  |  | | --- | --- | --- | | Acrobat gif | 本文档的 Acrobat 版本（48K）。 | [下载](https://developer.apple.com/library/archive/technotes/tb/pdf/tb_31.pdf) | |
